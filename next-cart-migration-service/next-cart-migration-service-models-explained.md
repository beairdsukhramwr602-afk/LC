# Next-Cart Migration Services

Next-Cart provides E-commerce Platform Migration Services through three Migration Services: Standard Service, Managed Service, and Custom Service. Each model supports a selected migration path from a Source Platform to a Target Platform under the purchased service license, but each model answers a different service question.

Standard Service is for customer-led migration execution. Managed Service is for Next-Cart-led execution within supported service capability. Custom Service is for requirements that need customization, modification, bespoke handling, Custom Platform review, Tailored Add-ons, Custom Add-ons, custom migration logic adjustment, or other custom-scoped work.

A good Migration Service decision is not based on data volume alone. Entity Points help define counted capacity, but the right Migration Service depends on the work required to produce a reliable target-store result. A store with high data volume can still be straightforward if the Source Platform, Target Platform, and data structure are well supported. A smaller store can still require Custom Service if important data depends on custom fields, third-party records, modified Add-on behavior, or custom migration logic.

### What Migration Services Clarify <a href="#what-migration-services-clarify" id="what-migration-services-clarify"></a>

Migration Services clarify responsibility and scope. They help customers understand who performs the migration actions, whether the requirement can stay within standard service capability, whether Add-ons are enough, and whether the project needs custom-scoped work.

| Service question                             | What the Migration Service helps clarify                                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Who performs migration actions?              | Whether the customer performs the actions or Next-Cart performs them based on the customer’s request and agreed scope.     |
| Is the migration within standard capability? | Whether the selected migration path and expected result can be handled without custom work.                                |
| Are Add-ons enough?                          | Whether filtering, mapping, or data configuration can be handled through available Add-ons.                                |
| Does the project need custom work?           | Whether the source store, target store, data structure, Add-on requirement, or platform condition needs tailored handling. |
| Who verifies the result?                     | The customer remains responsible for final result verification and migration outcome under every Migration Service.        |

The selected Migration Service should match the work needed for the migration, not only the customer’s preferred price point. Standard Service, Managed Service, and Custom Service are related, but they are not simply three sizes of the same package. Standard Service and Managed Service mainly differ in execution responsibility. Custom Service is different because it is used when the requirement needs work beyond standard capability.

### The Three Migration Services at a Glance <a href="#the-three-migration-services-at-a-glance" id="the-three-migration-services-at-a-glance"></a>

| Migration Service | Best understood as              | Main responsibility pattern                                                                                               | Typical fit                                                                                                                                                                 |
| ----------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Standard Service  | Customer-led migration          | The customer performs migration actions and verifies the result.                                                          | Supported migration paths with predictable requirements and customer-managed execution.                                                                                     |
| Managed Service   | Next-Cart-led migration         | Next-Cart performs migration actions based on the customer’s request and agreed service scope.                            | Supported migration paths where the customer wants expert execution support without custom-scoped work.                                                                     |
| Custom Service    | Custom-scoped migration service | Next-Cart reviews and handles agreed customization, modification, bespoke handling, or Expert Handle scope when included. | Projects involving Custom Platform handling, Tailored Add-ons, Custom Add-ons, custom fields, third-party data, custom migration logic, or other non-standard requirements. |

This distinction is important because “more support” and “custom work” are not the same decision. Managed Service helps when the migration can stay within supported capability but the customer wants Next-Cart to perform migration actions. Custom Service helps when the expected result requires custom handling, whether or not Next-Cart also performs the migration actions.

### Standard Service <a href="#standard-service" id="standard-service"></a>

Standard Service is the customer-led model for supported migration paths and standard requirements.

With Standard Service, the customer purchases a service license for the selected migration path, prepares the source store and target store, configures migration settings, performs migration actions, reviews the target-store result, and requests support when clarification is needed. Standard Service is suitable when the expected result can be achieved through standard migration capability and any selected Standard Add-ons.

Standard Service is usually suitable when:

* the Source Platform and Target Platform are supported for the selected migration path;
* the source-store data structure is predictable enough for standard handling;
* the customer can manage access preparation, configuration, execution, and result review;
* optional Standard Add-ons are enough for filtering, mapping, or data configuration needs;
* the project does not require custom migration logic, Custom Platform handling, third-party data handling, modified Add-on behavior, or bespoke data work.

Standard Service does not mean the customer is unsupported. Next-Cart support can help clarify service questions, configuration concerns, and migration issues. The defining point is execution responsibility: the customer performs the migration actions under the purchased service license.

### Managed Service <a href="#managed-service" id="managed-service"></a>

Managed Service is the Next-Cart-led model for supported migration paths where the customer wants expert execution support.

With Managed Service, Next-Cart performs migration actions based on the customer’s request and agreed service scope. This can reduce operational workload for customers who do not want to manage execution themselves, while keeping the migration within supported service capability and purchased Standard Add-ons where applicable.

Managed Service is usually suitable when:

* the migration path is supported and does not require custom-scoped work;
* the customer wants Next-Cart experts to perform migration actions;
* the migration needs coordinated execution rather than customer-led handling;
* available Standard Add-ons can support any filtering, mapping, or data configuration needs;
* the customer still wants to review the target-store result before launch or business use.

Managed Service does not automatically include customization. If the project requires custom fields, app data, plugin data, module or extension data, Custom Platform handling, modified Add-on behavior, Custom Add-ons, outside-system identifiers, or custom migration logic adjustment, the requirement should be reviewed through Custom Service.

The key difference between Standard Service and Managed Service is who performs the migration actions. The key difference between Managed Service and Custom Service is whether the project requires custom-scoped work.

### Custom Service <a href="#custom-service" id="custom-service"></a>

Custom Service is the model for requirements that need customization, modification, bespoke handling, or custom-scoped review.

A project may require Custom Service when the expected target-store result cannot be achieved through standard service capability and available Standard Add-ons alone. Custom Service should not be understood only as a larger or more expensive version of Standard Service. It is the service path for requirements that need work beyond standard capability.

Custom Service may be needed for:

* Custom Platform handling;
* custom fields or non-standard source-store structures;
* app, plugin, module, extension, or third-party data;
* outside-system identifiers;
* Tailored Add-ons that modify Standard Add-on behavior;
* Custom Add-ons created for project-specific needs;
* custom migration logic adjustment;
* platform limitations that require tailored handling;
* unusual data relationships that need bespoke review.

Custom Service identifies that custom work is required. It does not automatically mean Next-Cart performs every migration action for the customer. Execution responsibility depends on whether Expert Handle is included in the agreed Custom Service scope.

### Custom Service and Expert Handle <a href="#custom-service-and-expert-handle" id="custom-service-and-expert-handle"></a>

Custom Service can be customer-led or expert-handled depending on the agreed plan.

Custom Service without the Expert Handle option means Next-Cart handles the agreed custom work, customization, modification, or tailored requirement, while the customer performs the migration actions. This can fit customers who need custom capability but still want to operate the migration themselves.

Custom Service with the Expert Handle option means Next-Cart performs migration actions based on the customer’s request and agreed custom scope. This can fit customers who need both custom work and expert-led execution.

| Custom Service setup                 | Who performs migration actions?                             | What Next-Cart handles                                                                                                                            |
| ------------------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Custom Service without Expert Handle | Customer                                                    | Agreed custom work, customization, modification, Tailored Add-ons, Custom Add-ons, Custom Platform handling, or other custom-scoped requirements. |
| Custom Service with Expert Handle    | Next-Cart, based on the customer’s request and agreed scope | Agreed custom work plus expert-led migration execution within the custom plan.                                                                    |

The distinction matters because Custom Service describes the need for custom work. Expert Handle describes whether Next-Cart also performs the migration actions as part of the custom plan.

### How Add-ons Fit Across Migration Services <a href="#how-add-ons-fit-across-migration-services" id="how-add-ons-fit-across-migration-services"></a>

Add-ons are optional service features that support focused migration needs such as filtering, advanced mapping, or data configuration. Standard Add-ons can be used with Standard Service, Managed Service, or Custom Service when their available settings and supported behavior fit the requirement.

| Add-on situation                                                      | Migration Service meaning                                                                                |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Standard Add-on used within available settings and supported behavior | Can remain within Standard Service, Managed Service, or Custom Service depending on the broader project. |
| Standard Add-on needs modification beyond available behavior          | Should be reviewed through Custom Service as a Tailored Add-on.                                          |
| Required Add-on does not exist as a Standard Add-on                   | Should be reviewed through Custom Service as a Custom Add-on.                                            |
| Add-on is part of a broader custom-scoped migration                   | Included in Custom Service planning and quoting.                                                         |

For example, a Standard Service customer may use the Data Filter Add-on and perform migration actions independently. A Managed Service customer may purchase Standard Add-ons and ask Next-Cart to apply them within the agreed service scope. A Custom Service customer may use Standard Add-ons, Tailored Add-ons, or Custom Add-ons as part of a broader custom plan.

The important boundary is modification. An Add-on does not make a project custom just because it is purchased. A project becomes custom-scoped when the Add-on must be modified, extended, or created for a project-specific outcome.

### Customer Access and Final Verification <a href="#customer-access-and-final-verification" id="customer-access-and-final-verification"></a>

Customers using any Migration Service can access and perform available migration actions manually if they choose. The Migration Service determines responsibility, expert handling, and included service scope. It does not remove the customer’s ability to access the purchased migration service license.

With Standard Service and Custom Service without the Expert Handle option, the customer performs migration actions. With Managed Service and Custom Service with the Expert Handle option, Next-Cart performs migration actions based on the customer’s request and agreed service scope, while the customer can still perform available actions manually.

Under any Migration Service, the customer remains responsible for final result verification and migration outcome. Next-Cart can support, perform, or customize migration work depending on the selected Migration Service, but only the customer can confirm whether the target store meets the intended business expectations, launch requirements, and migration scope.

### How Service Status Can Change <a href="#how-service-status-can-change" id="how-service-status-can-change"></a>

A Migration Service can change when the project requirements become clearer. Demo Migration, Add-on review, source-store inspection, target-store planning, or Custom Platform review may show that the original service choice needs adjustment.

| Change discovered during planning or migration                                        | Likely service impact                                                           |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| A customer-led migration needs only supported settings and optional Standard Add-ons. | Standard Service may remain suitable.                                           |
| The customer wants Next-Cart to perform migration actions for a supported path.       | Managed Service may be more suitable.                                           |
| A Standard Add-on needs modification beyond available behavior.                       | The requirement should be reviewed through Custom Service as a Tailored Add-on. |
| The project requires app, plugin, extension, module, or third-party data handling.    | Custom Service should be reviewed.                                              |
| The project involves a Custom Platform or custom migration logic adjustment.          | Custom Service is usually required.                                             |
| The customer needs both custom work and Next-Cart-led migration execution.            | Custom Service with Expert Handle may be appropriate.                           |

Service status should reflect the work the migration actually needs. A project does not need a more supported Migration Service simply because the store is large, and a project should not stay in a lighter-touch Migration Service when the expected result requires custom work.

### Common Misunderstandings About Migration Services <a href="#common-misunderstandings-about-migration-services" id="common-misunderstandings-about-migration-services"></a>

#### “Managed Service and Custom Service mean the same thing.” <a href="#managed-service-and-custom-service-mean-the-same-thing" id="managed-service-and-custom-service-mean-the-same-thing"></a>

No. Managed Service is about Next-Cart-led execution within supported service capability. Custom Service is about customization, modification, bespoke handling, or custom-scoped requirements.

#### “Custom Service always means Next-Cart performs the entire migration.” <a href="#custom-service-always-means-next-cart-performs-the-entire-migration" id="custom-service-always-means-next-cart-performs-the-entire-migration"></a>

No. Custom Service means custom work is required. Next-Cart performs migration actions only when Expert Handle is included in the agreed scope.

#### “Standard Service means there is no support.” <a href="#standard-service-means-there-is-no-support" id="standard-service-means-there-is-no-support"></a>

No. Standard Service is customer-led, but customers can still request support. The customer remains responsible for performing migration actions.

#### “Add-ons always make the project Custom.” <a href="#add-ons-always-make-the-project-custom" id="add-ons-always-make-the-project-custom"></a>

No. Standard Add-ons can be used with Standard Service, Managed Service, or Custom Service. The project becomes custom-scoped when the Add-on needs modification beyond available behavior or when a Custom Add-on is required.

#### “Next-Cart-led execution removes the need for customer validation.” <a href="#next-cart-led-execution-removes-the-need-for-customer-validation" id="next-cart-led-execution-removes-the-need-for-customer-validation"></a>

No. The customer remains responsible for final result verification and migration outcome under every Migration Service.

### Conclusion <a href="#conclusion" id="conclusion"></a>

Standard Service, Managed Service, and Custom Service help customers understand how responsibility and scope should be handled during a Next-Cart migration. Standard Service is customer-led, Managed Service is Next-Cart-led for supported requirements, and Custom Service is used when the migration needs customization, modification, bespoke handling, Custom Platform review, Tailored Add-ons, Custom Add-ons, third-party data handling, or custom migration logic.

The strongest service choice starts with the expected target-store result. If the migration can stay within supported capability and the customer can perform the actions, Standard Service may be enough. If the customer wants Next-Cart to perform migration actions for a supported path, Managed Service may be safer. If the project needs custom work, Custom Service should be reviewed.

When the Migration Service is unclear after Demo Migration, Add-on planning, source-store review, or target-store planning, Live Chat can help clarify whether the migration should remain customer-led, become Next-Cart-led, or move into Custom Service.

### Common Questions <a href="#common-questions" id="common-questions"></a>

**What are the three Next-Cart Migration Services?**

The three Migration Services are Standard Service, Managed Service, and Custom Service.

**What is Standard Service?**

Standard Service is the customer-led model for supported migration paths and standard requirements. The customer performs migration actions under the purchased migration service license and reviews the target-store result.

**What is Managed Service?**

Managed Service is the Next-Cart-led model for supported migration paths. Next-Cart performs migration actions based on the customer’s request and agreed service scope.

**What is Custom Service?**

Custom Service is the model for migration requirements that need customization, modification, bespoke handling, Tailored Add-ons, Custom Add-ons, Custom Platform handling, custom migration logic, or other custom-scoped review.

**Does Custom Service always include the Expert Handle option?**

No. Custom Service can be purchased with or without the Expert Handle option. Without Expert Handle, the customer performs migration actions while Next-Cart handles the agreed custom work. With Expert Handle, Next-Cart performs migration actions based on the customer’s request and agreed custom scope.

**Can customers perform migration actions manually under any Migration Service?**

Yes. Customers using any Migration Service can access and perform available migration actions manually if they choose.

**Do customers still need to verify the result with Managed Service or Custom Service?**

Yes. Under any Migration Service, the customer remains responsible for final result verification and migration outcome.

**Can Add-ons be used with every Migration Service?**

Yes. Standard Add-ons can be used with Standard Service, Managed Service, or Custom Service when their available settings and supported behavior fit the requirement.

**When does an Add-on require Custom Service?**

An Add-on requirement should be reviewed through Custom Service when it needs modification beyond available Standard Add-on behavior or when the customer needs a Custom Add-on.

**How should customers choose a Migration Service?**

Customers should consider whether the migration can stay within standard capability, whether Add-ons are enough, who should perform the migration actions, whether custom work is required, and whether Expert Handle is needed.
